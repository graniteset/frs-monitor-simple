# Board-independent IQ test stream

This directory contains a small, synthesizable SystemVerilog foundation for
testing receive DSP before connecting a specific PlutoPlus/AD9363 board design.
It deliberately does not define clocks, pins, AXI-Lite registers, DMA, or any
vendor-specific IP integration.

## Reference receive-chain specification

The board-independent core is being built to match the current GNU Radio
graph at its default 6.4 MS/s complex input rate:

| Stage | GNU Radio reference | Rate / format |
|---|---|---|
| RF input | center 465.125 MHz; signed complex IQ | 6.4 MS/s |
| Two band translators | centers 462.6375 and 467.6375 MHz; 205-tap Hamming LPF (100 kHz cutoff, 75 kHz transition); decimate 16 | 400 kS/s per band |
| Sparse PFBs | two 32-bin banks, oversample 2; 241-tap Hamming prototype (6 kHz cutoff, 4 kHz transition) | selected bins at 25 kS/s |
| Selected channel offsets | `round((channel_hz - band_center)/12.5k) mod 32`; first bank has 15 outputs, second has 7 | 22 complex channels |
| Squelch | `simple_squelch_cc(threshold_db, alpha)`; average magnitude-squared power and mute below threshold | complex, 25 kS/s |
| FM demodulation | quadrature discriminator; max deviation 2.5 kHz; gain `25k/(2*pi*2500)` | float, 25 kS/s |
| De-emphasis and audio filter | 75 us bilinear-IIR de-emphasis; 121-tap Hamming LPF (2.7 kHz cutoff, 500 Hz transition); decimate 2 | mono audio, 12.5 kS/s/channel |

GNU Radio's oversampled channelizer maps a +75 kHz tone at 400 kS/s to bin 6.
Its per-channel phase has a constant bin-dependent offset; FM demodulation is
invariant to that constant phase. The PFB test follows GNU Radio's native
phase convention and ignores the differing startup frames until the long FIR
settles.

The internal fixed-point boundary is signed 16-bit Q1.15 IQ/audio and signed
18-bit Q1.17 FIR coefficients. The portable top accepts signed 12-bit ADC I/Q
and currently converts it to Q1.15 by shifting left four bits. Confirm the
actual ADI `ad_datafmt` mode before hardware hookup: a 16-bit transport word
does not imply 16 effective ADC bits. A 241-tap worst-case FIR sum needs at least
42 signed accumulator bits (34-bit product plus 8 guard bits). Round to
nearest when returning to Q1.15 and saturate rather than wrap. The GNU Radio
float implementation remains the golden reference; expected fixed-point error
must be measured on representative tones, noise, and modulated signals.

The generic top-level interface is implemented in `frs_receive_core.sv` and
produces one time-multiplexed audio output beat with a 5-bit FRS channel ID
(1..22) and signed 16-bit Q1.15 audio (12.5 kS/s per channel, 275 kS/s
aggregate). This avoids exposing 22 independent audio handshakes.

The board-independent chain now composes both bands through the channelizers,
merges tagged IQ and uses a shared 22-channel audio processor. The first DSP
blocks are `band_ddc_decimator.sv` and `sparse_channelizer.sv`.
The DDC matches a GNU Radio float golden vector after Q1.15 quantization. The
sparse channelizer computes selected bins with two complex taps per clock and
has been compared against GNU Radio's oversample-2 32-bin PFB using an adjacent
carrier 18 dB stronger than the desired carrier. Its fixed-point output and
adjacent-bin isolation pass the independent testbench. NCO and tap files are
generated by `generate_assets.py`; golden vectors are generated by
`generate_ddc_vectors.py` and `generate_pfb_vectors.py`. The checked-in files
let ordinary simulation run without GNU Radio.

The DDC accepts one complex Q1.15 sample on each `s_valid && s_ready` event.
It decimates by 16, uses a 9-bit phase accumulator/NCO and the checked-in
205-tap Q1.17 filter. Its serialized MAC takes 205 fabric clocks per output;
at a 100 MHz fabric clock this is comfortably below the 250 clocks between
400 kS/s subband samples. The initial phase is chosen to match GNU Radio's
steady-state output phase. Its `s_ready` only stalls if the next decimated
sample arrives before the previous MAC completes; at 100 MHz, 6.4 MS/s input
and 400 kS/s output, the 205-cycle MAC fits within the 250-cycle output
interval. A non-stallable source still needs buffering for clock-domain or
burst-rate differences.

The `complex_squelch.sv` block tracks complex magnitude-squared power using a
Q1.15 EMA coefficient and a host-programmed Q30 linear threshold. Its test
covers opening/closing and stalled-stream stability. `quadrature_demod.sv`
implements the FM discriminator with a 16-step iterative CORDIC and matches
GNU Radio within 8 Q1.15 LSB on a varying-deviation signal.

The scalar `fm_deemphasis.sv` uses 75 us bilinear coefficients quantized to
Q1.17; its test differs from GNU Radio by at most 3 LSB. The scalar
`audio_fir_decimator.sv` applies the 121-tap 2.7 kHz low-pass and decimates by
two, also matching within 3 LSB on the checked-in test vector. These stages
are composed in `frs_channel_audio.sv`, a complete single-channel tagged-audio
path with the current 0.25 gain; the end-to-end vector comparison passes
within 4 LSB. `frs_multi_channel_audio.sv` keeps per-channel squelch EMA,
discriminator history, de-emphasis state, decimator phase, and 121-sample
audio history while sharing one iterative CORDIC and one audio FIR worker.
Every deemphasized sample is queued so the 2.7 kHz low-pass precedes ÷2
decimation. `axis_rr_merge2_iq.sv` merges the two band outputs with a stable
grant under backpressure. The 22-channel golden test varies downstream
readiness and matches GNU Radio within 3 LSB. This is portable RTL, not a
timing-closed Vivado build.

The sparse channelizer uses two complex taps (eight real products) per MAC
clock. With 22 selected outputs it needs about 2,662 MAC clocks plus output
serialization for each 16-sample frame. At a 100 MHz clock, that is below the
4,000-cycle interval between frames at 400 kS/s; its 512-entry history ring
allows the input to continue during calculation. If the clock or input timing
differs, `overrun` flags missed frames. Both bands and the serialized audio
processor are composed in `frs_receive_core.sv`; board clocks, CDC/input
buffering, DMA, and control registers intentionally remain outside this core.

## Blocks

- `iq_test_source.sv`: continuous AXI4-Stream IQ source. Each beat is packed as
  `{I[15:0], Q[15:0]}` in signed two's-complement. A 32-bit phase accumulator
  drives a small lookup-table sinusoid. `ON_SAMPLES` tone samples are followed
  by `OFF_SAMPLES` all-zero samples, repeatedly. `phase_step` is captured as
  samples are produced; its tuning relation is `f/Fs = phase_step / 2^32`.
  `GAIN_Q15` is a compile-time amplitude control (32768 means unity; values
  from zero through 32768 avoid clipping).
  Data and `TVALID` are registered and held stable during downstream stalls.
- `frs_fm_test_source.sv`: deterministic board-integration stimulus at the
  6.4 MS/s FRS input rate. It generates an on-channel channel-4 complex NBFM
  carrier (462.6375 MHz relative to a 465.125 MHz LO), with a 1 kHz sine
  message, +/-1 kHz deviation, and repeatable 50 ms transmit / 500 ms quiet
  periods by default. Its 1024-entry Q1.15 sine ROM is generated by
  `generate_test_sine_lut.py`. The bridge uses this only when built with
  `TEST_MODE=1`; live-radio builds keep the radio input path selected.
- `axis_iq_mux.sv`: 2:1 stream mux to choose between live IQ and test IQ. The
  chosen input is locked while an output beat is stalled. The caller supplies
  `select`; 0 selects A (e.g. radio), 1 selects B (test source).
- `band_ddc_decimator.sv`: one Q1.15 complex mixer and 205-tap, ÷16 band
  filter, with NCO tuning configured by phase-step parameters.
- `sparse_channelizer.sv`: one sparse 32-bin, oversample-2 bank with tagged,
  serialized selected-bin IQ output.
- `complex_squelch.sv`, `quadrature_demod.sv`, `fm_deemphasis.sv`, and
  `audio_fir_decimator.sv`: independently tested scalar channel stages.
- `frs_channel_audio.sv`: composition of those scalar channel stages into one
  tagged mono-audio stream with configurable channel number and gain.
- `axis_rr_merge2_iq.sv`: round-robin merger for two tagged band outputs.
- `frs_multi_channel_audio.sv`: shared post-channelizer worker with
  independent state and delay history for all 22 FRS channels.
- `frs_receive_core.sv`: portable dual-band chain from signed 12-bit input I/Q
  through time-multiplexed tagged 12.5 kS/s audio.
- `tb_iq_stream.sv`: self-checking simulation test for tone sequence, burst
  gaps, source backpressure/reset behavior, and mux routing/selection locking.

The quarter-wave table is intentionally compact, so it is appropriate for
functional DSP verification, not a high-purity RF signal source. Improve LUT
depth or use vendor DDS IP if spur performance becomes important.

## Simulation

With Icarus Verilog installed, run:

```sh
make fpga-test
```

The target runs the IQ source/mux, DDC-versus-GNU-Radio, sparse PFB versus
GNU Radio, squelch, FM discriminator, de-emphasis, audio FIR, composed
single-channel and 22-channel audio tests, the dual-band merge ordering and
backpressure test, and a full-core 12-bit-input smoke test that checks all 22
output tags and catches unknown startup samples. The PFB test also checks
desired-bin energy beside a much stronger adjacent carrier.

To regenerate the checked-in DSP assets/vectors (requires GNU Radio Python
bindings): run `generate_assets.py`, `generate_ddc_vectors.py`,
`generate_pfb_vectors.py`, `generate_fm_vectors.py`, then
`generate_audio_vectors.py`, in that order.

No Vivado board project or simulator is included in this repository yet. Add
these generic blocks at the eventual receive-DSP input and adapt only the
wrapper/control interface to that board's existing AD936x design.
